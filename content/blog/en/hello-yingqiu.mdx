For the past while, this portfolio lived on GitHub Pages at `yuning-gu.github.io`. After a GitHub username change, that address quietly stopped working — and it was a good excuse to do something I had wanted for a long time.

## What changed

- **Own domain.** The site now lives at `yingqiu.me`, with clean `https://` served by [Caddy](https://caddyserver.com) (automatic TLS, nothing to renew by hand).
- **Own server.** The site is plain static files — HTML, CSS, and JavaScript — built by GitHub Actions and synced to a small VPS. No database, no Node process to babysit.
- **A blog.** This page. Posts are written in Markdown / MDX, one file per language, and compiled into the site at build time.

## Why static?

> A static site is fast, cheap to host, and nearly impossible to break. Every page is a file; every deployment is a `rsync`.

That matters for a site whose main job is to stay up while I am busy in the lab. The build runs `npm run build`, produces the whole site into `out/`, and deployment is one command:

```bash
NEXT_PUBLIC_SITE_URL=https://yingqiu.me npm run build
rsync -az --delete out/ deployer@yingqiu.me:/var/www/site/
```

## What comes next

1. Keep the portfolio content up to date (publications, experience).
2. Write here — research notes, reading summaries, and things I learn about drug development.
3. Polish the details: analytics-free, low-dependency, and bilingual throughout.

You can subscribe via [RSS](/feed.xml) if you prefer feeds over bookmarks. And if anything looks broken, the [contact page](/en/contact/) is the fastest way to reach me.
